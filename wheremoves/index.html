WhereMoves: Informative and Efficient Point Trajectory WAMs by Anticipating Where Motion Will Occur

Om Khangaonkar1, Ahmadreza Moradipari2, Kyungtae Han2,
Shatadal Mishra2, Soheil Kolouri3, Hamed Pirsiavash1

1University of California, Davis 2Toyota Motor Corporation 3Vanderbilt University

arXiv soon Code Data Models soon

TL;DR: WhereMoves learns where future motion will occur before predicting how it will unfold. We select representative pixels and group pixels with similar motion, then generate a few trajectories and propagate their displacements within each group. This improves both the WAM's efficiency and the downstream success rates.

Motivation

World-action models (WAMs) are only useful for robots if they anticipate informative changes in the scene. Many world models do this by generating future video frames. Forecasting future motion as point trajectories is emerging as a promising alternative to video prediction, as it provides correspondences for free and does not require generating appearance.

These models select points, anticipate their future motion, and condition a robot policy on the predicted trajectories. However, we observe that the usefulness of these anticipated trajectories depends not only on how accurately the points move, but also on which points we choose to anticipate.

Existing approaches typically select points heuristically (i.e. grid selection, feature clustering). However, there are two main problems with this. First, heuristic selection disregards where the scene is likely to move, so it can miss moving objects and select static or irrelevant pixels, hurting the performance of the downstream policy. Second, it does not account for which parts have similar motion, so it predicts redundant trajectories, increasing point trajectory generation compute linearly (at best) with the number of points.

We argue that point trajectory WAMs should instead learn which points to select, based on where future motion will occur. This enables WhereMoves to predict which object the robot is reaching for from visual context alone. For example, our model places points on only the drill and the robot arm based on the robot’s pose. In contrast, heuristic selection tends to miss moving objects and anticipates (mostly static) motion for irrelevant objects.

Method

Our core insight is that we should predict which pixels will move together, and which set of points will best represent that motion before generating the future motion itself.

Learning where distinct motion occurs

We formulate this as jointly localizing pixels representing distinct and informative future motions and grouping pixels with redundant future motion. Our model takes the first frame and K as input and jointly predicts K representative pixels and a per-pixel motion-group assignment.

We predict K + 1 motion groups, where the additional motion group represents “background” pixels with static or irrelevant motion. We then forecast motion for only the K representative pixels.

Future motion provides the supervision

How can the model learn these points and groups from a single image? To train our model, we leverage future motion as supervision for selecting and grouping pixels in the present.

First, we filter out static or uninformative trajectories (corresponding to our additional motion group). Then, for a given K, we cluster the remaining trajectories into K groups by their displacement over time. Each cluster provides us with a representative pixel (its center’s pixel location) and the motion group (the pixel locations of other trajectories in the cluster, and which representative pixel they correspond to).

We take inspiration from prior work in object detection, DETR, and formulate point selection as predicting an unordered set of K locations. We formulate motion grouping as segmentation in a learned feature space optimized with a contrastive loss. Our model jointly attends over the image patches and representative pixel tokens to produce an unordered set of representative pixel locations, and pixel-level motion features.

We learn to accurately predict the pixel location via bipartite matching and a regression loss. In addition, we learn to accurately predict motion features via a contrastive InfoNCE loss that pulls together embeddings from the same motion group while pulling apart from other groups.

Note that our training uses future tracks for supervision, while inference uses only the current image.

Motion groups let us reuse predictions

Selecting representative points also gives us a way to avoid predicting redundant motion. In some settings, we may only have the computational budget to predict K distinct trajectories, while a downstream task, e.g., a robot policy, requires N > K point trajectories.

To upsample the representative motions to every pixel, we simply assign each pixel its corresponding representative pixel’s displacement trajectory.

Because the predicted motion groups enable us to map predicted trajectories to pixels with similar future motion, we can decouple the number of trajectories we need to generate from the number of trajectories the policy is conditioned on. For example, we can generate just four distinct trajectories and expand them to 256 policy inputs using a nearest-neighbor upsample.

Results

We next test whether these trajectories help the robot complete its task. Our learned trajectory selection substantially outperforms baselines in success rate, efficiency, or both. With eight generated trajectories per camera, WhereMoves achieves 54.3% success, compared with 1.2% for grid selection at the same point count.

We report success rate over 50 rollouts for each of the 24 RoboCasa tasks. We also report GFLOPs and inference time for generation and selection on an NVIDIA RTX 3090.

We plot success rates on RoboCasa as the number of generated trajectories per camera, K, increases. The area of the translucent disk represents the sum of generation and selection costs in GFLOPs.

We demonstrate that generating very few trajectories (i.e. 4 or 8) and upsampling using our learned motion group embeddings performs very close to the full 256 trajectories, and still strongly outperforms baselines. This suggests on many tasks, policies may only need distinct motion from a few points to perform well.

Given the effectiveness, speed, and flexibility of our method, we hope that future world models will benefit from learning where distinct future motion will occur.
